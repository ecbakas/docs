# Optional Invoice Number Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every tag-create form that shows an invoice-number input makes it optional and says a number will be generated; submitting blank posts `INV-<epoch-ms>`.

**Architecture:** One pure `resolveInvoiceNumber(typed, now)` per repo decides typed-vs-generated, and every create path calls it instead of reading the raw field. The input keeps its empty string on screen — generation happens at submit only — so the description stays true. The required `*` and the three submit gates that refuse a blank number come out.

**Tech Stack:** super-app = Expo / React Native / NativeWind / jest. web-app = Next.js App Router / React / Tailwind / `@repo/ayasofyazilim-ui` / playwright (e2e only).

**Spec:** [`docs/superpowers/specs/2026-08-04-optional-invoice-number-design.md`](../specs/2026-08-04-optional-invoice-number-design.md)

## Global Constraints

- **Two separate git repos.** `c:\unirefund\super-app` and `c:\unirefund\web-app` are independent repos, both currently on `main`. Create a feature branch in each before the first commit in that repo. Never run `git reset --hard` in `super-app` — another agent session may share that checkout.
- **Generated number format:** `` `INV-${now}` `` where `now` is epoch milliseconds. Identical in both repos; each definition carries a comment naming the other.
- **Copy is fixed, verbatim:**
  - EN: `Leave empty to have one generated automatically.`
  - TR: `Boş bırakırsanız otomatik olarak oluşturulur.`
- **No hardcoded UI strings.** Both locales get the key before any component reads it.
- **Never edit generated files.** Not `super-app/src/data/language-data/*.gen.json`, not `web-app/apps/web/src/language-data/i18n/*.gen.json`, not `**/saas/**`. Regenerate with the repo's `init` script.
- **`t[...]` is typed from the generated bundle.** A key added only to `resources/*.json` does not typecheck until `init` runs. Key first, `init` second, component third — in that order, inside one task.
- **No `useEffect`** for anything in this plan. Nothing here needs one.
- **web-app `data-testid`:** required on `Label`, `Input`, `Button`, and the other components listed in `web-app/.claude/rules/data-testid.md`. Plain HTML elements (`p`, `div`, `span`) are exempt — the new hint is a `<p>` and needs none.
- **super-app styling:** semantic token classes (`text-muted`, `text-foreground`), not hardcoded colours.
- **Commit at the end of every task**, in the repo that task touched.

/**
 * The invoice number posted when the operator leaves the field empty.
 *
 * `now` is injected rather than read from the clock so callers stay testable —
 * the same discipline `buildStickerTagRequest` applies to `issueDate`.
 *
 * Millisecond precision, so two creates inside the same millisecond collide.
 * That is not a human-reachable rate, and `InvoiceRequestDto.invoiceNumber`
 * carries no uniqueness constraint — it is an optional external reference. A
 * uuid suffix would only make the number unreadable aloud.
 *
 * web-app repeats this format in `components/tag-form/invoice.ts`. There is no
 * package shared between the two apps, so change both or neither.
 */
export function generateInvoiceNumber(now: number): string {
  return `INV-${now}`;
}

/**
 * A typed invoice number wins; blank or whitespace-only falls back to a
 * generated one.
 *
 * Trimmed before the emptiness test, not after: the field is free text, so a
 * space typed into it is "empty" as far as the operator is concerned, and
 * posting " " as an invoice number would be worse than generating one.
 */
export function resolveInvoiceNumber(
  typed: string | null | undefined,
  now: number,
): string {
  return typed?.trim() || generateInvoiceNumber(now);
}
```

/**
 * The invoice number posted when the operator leaves the field empty.
 *
 * Millisecond precision, so two creates inside the same millisecond collide.
 * That is not a human-reachable rate, and `InvoiceRequestDto.invoiceNumber`
 * carries no uniqueness constraint — it is an optional external reference.
 *
 * super-app repeats this format in
 * `screens/shared/_components/tag-calculator/line.ts`. There is no package
 * shared between the two apps, so change both or neither.
 */
export function generateInvoiceNumber(now: number): string {
  return `INV-${now}`;
}

/**
 * A typed invoice number wins; blank or whitespace-only falls back to a
 * generated one.
 *
 * Trimmed before the emptiness test, not after: the field is free text, so a
 * space typed into it is "empty" as far as the operator is concerned, and
 * posting " " as an invoice number would be worse than generating one.
 */
export function resolveInvoiceNumber(
  typed: string | null | undefined,
  now: number
): string {
  return typed?.trim() || generateInvoiceNumber(now);
}

/**
 * The invoice as it should be posted: its number resolved, everything else
 * untouched.
 *
 * Every create path goes through this rather than reading `invoice.invoiceNumber`
 * directly, so the three pages that build a create body cannot disagree about
 * when a number is generated.
 *
 * Deliberately *not* applied to the state behind the input. The operator is told
 * a number will be generated if they leave the field empty, so filling the field
 * in before submit would contradict the very hint under it — and would put a
 * number on screen that they would then reasonably try to reconcile against the
 * paper invoice in front of them.
 *
 * `now` defaults to the clock because no caller needs to pin it; the parameter
 * exists so it can be pinned if `apps/web` ever gains a unit-test runner.
 */
export function invoiceForSubmit(
  invoice: InvoiceRequestDto,
  now: number = Date.now()
): InvoiceRequestDto {
  return {
    ...invoice,
    invoiceNumber: resolveInvoiceNumber(invoice.invoiceNumber, now),
  };
}
```
