# Attested Assisted Scan (UNI-1817) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the two held assisted-scan flows onto UNI-1817's endpoint and add the QR-less "attest at your exit point post" path. The flows are web `operations/assisted-qr-scan` and super-app `AssistedValidate`.

**Architecture:**
- **One submit:** both apps send `POST /api/export-validation-service/qr-evidence/scan-with-traveller-info`. The body carries exactly one anchor: `exitPointPostId` (attested) or `qrValue` (kiosk QR).
- **The picker:** `GET /api/crm-service/exit-point-posts/mine` is read once when the flow opens. It feeds a post picker:
  - 0 posts → attesting is unavailable, so show a message and the kiosk QR only;
  - 1 post → a disabled picker with that post pre-selected;
  - 2+ posts → the user must pick one.
- **The QR stays as an alternative** for anyone standing at a kiosk.
- **Unchanged:** one form and one result view.

**Tech Stack:**
- **web-app:** Next.js 16 / React 19, `apps/web` plus `packages/actions` and `packages/saas`. Gates: Node `test:unit`, tsc, eslint, i18n scripts.
- **super-app:** Expo / React Native, `src/saas` client. Gates: jest (`*.router.test.*` for render tests), tsc.

**Spec:** UNI-1817 "Agreed design (2026-10-14)", D1–D7 (https://clomerce.atlassian.net/browse/UNI-1817). The backend is PR UniRefund#2337, live on dev on 2026-10-27, and the swagger was checked.

## Review Focus

1. **One post:** the picker shows it pre-selected and disabled, and the request still carries its `exitPointPostId`. (Web Task 2 `postChoice` tests; super-app Task 5 router test.)
2. **No grant, a failed read, or 0 posts:** the flow still works with the kiosk QR and shows the "no post" message, never an error page. (Web Task 2/3; super-app Task 5.)
3. **Exactly one anchor in every request:** the attested submit sends no `qrValue`, and a QR submit sends no `exitPointPostId`. (Web Task 2 request tests; super-app Task 4 logic tests.)
4. **`010022` has its own message.** It is not "QR expired" and not a generic failure. (Web Task 2 `classifyScanFailure`; super-app Task 4.)
5. **Choosing a post never opens the camera.** The QR path stays reachable from the same step. (Web Task 3; super-app Task 5.)

Rules:
- **QR anchor:** `parseKioskQrInput(anchor.qrValue)`; null → `"qr"`. The body gets `qrValue` and **no** `exitPointPostId` key.

- **Validation order:** anchor first, then location, traveller and flight, as today.
- **`postChoice`:**

  - exactly one item → `single`;
  - two or more items → `choose`, in the server's order.
- **`classifyScanFailure`:** `${ERROR}010022` → `"not-assigned"`.
