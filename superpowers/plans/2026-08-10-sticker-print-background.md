# Sticker Label Print Background Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an "Add background" toggle to the sticker label print modal that rasterises `unirefund_sticker_70x100mm.pdf` and prints it as artwork behind every label's QR code.

**Architecture:** A standalone client module rasterises page 1 of the PDF to a 300 DPI PNG data URL via a lazily imported `pdfjs-dist`. The print modal caches that data URL in component state and renders it as an `<img>` filling each 70x100mm label, beneath the existing QR. `react-to-print` and the print stylesheet are untouched, so the preview and the printed output stay identical.

**Tech Stack:** Next.js 16 (App Router, Turbopack), React 19, TypeScript, `pdfjs-dist` 5.4.296, `react-to-print`, `react-qr-code`, `@repo/ayasofyazilim-ui`.

**Spec:** `docs/superpowers/specs/2026-08-10-sticker-print-background-design.md`

## Global Constraints

- All work is in `web-app/`. Run every command from `web-app/` (the git repository root). Current branch: `feat/manual-verification`.
- `pdfjs-dist` must be pinned to `^5.4.296` — the exact version `react-pdf@^10.2.0` already resolves inside `@repo/ayasofyazilim-ui`, so pnpm reuses the store entry instead of adding a second copy.
- Never hardcode a user-visible string. Every one is a key in **both** `en.json` and `tr.json` under `apps/web/src/language-data/unirefund/TagService/resources/`.
- Never edit files in `apps/web/src/language-data/i18n/` — they are generated by `pnpm run init`.
- `pnpm run init` must be run after adding i18n keys, before `type-check` can resolve them.
- No `useEffect`. Per `web-app/.claude/rules/avoid-use-effect.md`, this is an event-driven update and belongs in the `onCheckedChange` handler.
- `Switch` and `Label` both require a `data-testid` (enforced by the `react-require-testid/testid-missing` ESLint rule). Plain HTML elements such as `img` are exempt.
- The QR code does not move. It stays 20x20mm, 20mm from the top, 10mm from the right, in both the background and no-background cases.

## Verification Reality

`apps/web` has **no unit test runner** — `pnpm --filter web test` runs Playwright, and those specs need a live authenticated environment (`auth.setup.ts`, a `baseURL` from `.env`) plus a seeded sticker book. The print modal has no automated coverage today and this plan does not add a test runner for it.

So each task is gated on `type-check` + `lint`, and the final task on a manual print-preview check. Where a step says "expected", that is the literal output to confirm before moving on. Do not report a task complete without running its commands.

- [ ] **Step 4: Write the rasteriser**

Create `apps/web/src/app/[lang]/(main)/(unirefund)/operations/stickers/[stickerId]/_components/sticker-label-background.ts`:

```ts
"use client";

const BACKGROUND_PDF_URL = "/unirefund_sticker_70x100mm.pdf";

/**
 * 70mm at 300 DPI. The artwork is rasterised to this width and the label's
 * `<img>` stretches it back to 70mm, so the printed background lands at 300 DPI
 * whatever the browser's own print scaling does.
 */
const LABEL_WIDTH_PX = 827;

/**
 * Rasterises the sticker artwork to a PNG data URL.
 *
 * `pdfjs-dist` is imported lazily rather than at module scope: it is ~350KB that
 * only an operator who ticks the background toggle ever needs, and deferring it
 * keeps pdf.js out of the server render of this client component entirely.
 */
export async function loadStickerBackground(): Promise<string> {
  const pdfjs = await import("pdfjs-dist");

  // Resolved by the bundler rather than fetched from a CDN. A printed sticker is
  // permanent, so a CDN outage must not be able to degrade a print run.
  pdfjs.GlobalWorkerOptions.workerSrc = new URL(
    "pdfjs-dist/build/pdf.worker.min.mjs",
    import.meta.url
  ).toString();

  const pdf = await pdfjs.getDocument(BACKGROUND_PDF_URL).promise;
  try {
    const page = await pdf.getPage(1);
    // Scale is derived from the page's own width rather than an assumed
    // 198.43x283.46pt box, so artwork whose page size drifts from 70x100mm
    // still rasterises at 300 DPI instead of silently softening.
    const scale = LABEL_WIDTH_PX / page.getViewport({ scale: 1 }).width;
    const viewport = page.getViewport({ scale });

    const canvas = document.createElement("canvas");
    canvas.width = Math.round(viewport.width);
    canvas.height = Math.round(viewport.height);

    await page.render({ canvas, viewport }).promise;
    return canvas.toDataURL("image/png");
  } finally {
    void pdf.destroy();
  }
}
```

Two API details that are easy to get wrong on pdf.js 5.x:
- `page.render()` takes `canvas`, not `canvasContext`. `canvasContext` still exists but is the deprecated back-compat path.
- `getDocument()` returns a loading task, not a promise — the `.promise` property is required.

- [ ] **Step 2: Give `StickerLabelPage` a background**

Add `backgroundUrl` to its props and render it beneath the QR. The `<img>` is first in the DOM so the QR stacks above it without needing a z-index.

```tsx
function StickerLabelPage({
  backgroundUrl,
  label,
  pageBreakBefore,
}: {
  backgroundUrl: string | null;
  label: StickerLabel;
  pageBreakBefore: boolean;
}) {
  return (
    <div
      className={`relative h-[100mm] w-[70mm] shrink-0 overflow-hidden break-inside-avoid border bg-white print:border-0 ${
        pageBreakBefore ? "break-before-page" : ""
      }`}
    >
      {backgroundUrl ? (
        // An <img> rather than a CSS background: background images print only
        // when the operator has ticked "Background graphics" in the print
        // dialog, which would let a whole book print blank without warning.
        <img alt="" className="absolute inset-0 h-full w-full" src={backgroundUrl} />
      ) : null}
      {label.qrValue ? (
        <QRCode
          className="absolute top-[20mm] right-[10mm] h-[20mm] w-[20mm]"
          level="M"
          value={label.qrValue}
        />
      ) : (
        // Nothing is written on a label, so an unencodable line number leaves an
        // empty outline rather than a page that reads as blank by design.
        <div className="absolute top-[20mm] right-[10mm] h-[20mm] w-[20mm] border-2 border-dashed border-black/30" />
      )}
    </div>
  );
}
```

- [ ] **Step 4: Add the change handler**

Beside `handleUnusedOnlyChange`:

```tsx
function handleBackgroundChange(checked: boolean) {
  setWithBackground(checked);
  // Rasterised once per dialog session - toggling off and back on reuses it.
  if (!checked || background) return;

  startBackgroundTransition(async () => {
    try {
      setBackground(await loadStickerBackground());
    } catch {
      // Reverted rather than left on: a toggle reading "on" over a run that
      // would print without artwork is the one outcome worth preventing.
      setWithBackground(false);
      toast.error(
        t.TagService["StickerHeader.PrintLabels.BackgroundUnavailable"]
      );
    }
  });
}
```

## Known Risks

| Risk | Detection | Response |
| ---- | --------- | -------- |
| Turbopack does not resolve the bundler worker URL | pdf.js "fake worker" console warning, or a 404 for `pdf.worker.min.mjs` | Copy the worker into `public/` from `init.ts` (Task 3, Step 10). Not the CDN. |
| Artwork page box is not exactly 70:100 | Preview artwork looks stretched | Expected and accepted — the `<img>` fills the label because the artwork *is* the label. A visible distortion means the asset is wrong, not the code. |
| Artwork renders with missing glyphs | Blank or boxed text in the preview | pdf.js needs `standard_fonts/` for non-embedded fonts. If it happens, copy that directory into `public/` and pass `standardFontDataUrl` to `getDocument`. |
| Data URL is large enough to stall a big book | Preview visibly slows after ticking the toggle | All labels share one `src`, so the browser decodes the bitmap once. If it still stalls, drop `LABEL_WIDTH_PX` to 600 (~218 DPI). |
