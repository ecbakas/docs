# Removing unused localization keys from web-app

**Date:** 2026-08-05
**Scope:** `web-app/apps/web` (primary), `web-app/apps/ssr` (follow-up)
**Status:** approved design, ready for implementation planning

## Problem

`apps/web/src/language-data/{core,unirefund}/*/resources/{en,tr}.json` hold 3,351 English
keys across 18 service folders. Many are leftovers from removed or reworked features. Nothing
in the repo detects them, so they accumulate: translators localize dead strings, and the
files are hard to review.

A naive grep is not good enough. Keys are also reached through four indirect mechanisms, and
each one hides live keys from a literal search:

| Mechanism | Example | Live keys hidden |
| --- | --- | --- |
| Template literal | `` t.RefundService[`Batches.status.${status}`] `` | 210 prefix families |
| Schema-form derivation | `createUiSchemaWithResource({ name: "Form.Role" })` builds `Form.Role.<field>` from generated SDK schemas | 44 prefix families |
| Prefix constant + API value | `SETTING_KEY_PREFIX = "CountryManagement."` in `setting-values.ts`, read via `languageData[item.displayName]` | 255 keys |
| Config-object indirection | `languageData[navItem.displayName]` where `data.ts` supplies the literal | none — the config values are literals, so a substring scan already covers them |

Naive matching reports 975 dead keys. 548 of those are reachable, or conservatively guarded as
reachable, once the mechanisms above are accounted for.

## Goals

- Delete keys that no code path can reach, from both `en.json` and `tr.json`.
- Leave behind a committed, re-runnable detector so this does not silently regrow.
- Take zero risk with keys that are reachable only at runtime.

## Non-goals

- `apps/web/src/language-data/resources.ts` — ABP resource *types*, not JSON. Out of scope by
  request.
- `apps/*/src/language-data/i18n/*.gen.json` — generated by `init.ts` and gitignored.
- Server-side ABP localization resources, which `init.ts` merges in at build time. Only the
  local JSON files are touched.
- Migrating `getResourceData` call sites to `getTranslations`. Unrelated to this cleanup.

## Approach

A text scanner with layered guards, committed as `web-app/scripts/find-unused-i18n.mjs`.

It lives at the workspace root, not under `apps/web`, because it serves both apps. There is no
existing `scripts/` directory, so this creates one. Plain `.mjs` run by `node` avoids adding a
`tsx` dependency at the root — `apps/web/init.ts` gets `tsx` from the app's own devDependencies,
which the root does not have.

Two alternatives were considered and rejected. A **TypeScript AST analysis** (ts-morph) would
resolve member accesses and schema `$defs` precisely, letting it prune stale `Form.*` keys that
the text scanner must keep — but it is far more code, brittle against the three coexisting read
patterns, and still blind to `languageData[apiSuppliedValue]`, so it does not remove the need
for an allowlist. **Runtime instrumentation** (proxy the resource objects, drive the Playwright
suite, record reads) gives ground truth for exercised paths but inverts the risk: unvisited
pages look dead, so it would delete live keys.

### Corpus

- `apps/<app>/src`, excluding `language-data`
- `packages/**` (shared by `web` and `ssr`; `packages/ui` and `packages/ayasofyazilim-ui`
  reference keys as literals)
- Extensions `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`; skip `node_modules`, `.next`, `.turbo`, `dist`
- File paths are appended to the corpus as cheap insurance against route-segment keys. This
  currently rescues nothing, but costs one line.

### Guard layers

A key is **kept** if any layer matches. Only keys matching none are dead.

1. **Literal** — the key text appears anywhere in the corpus, as a plain substring, tested in
   both its raw form and its JSON-escaped form. Substring rather than quoted-literal matching is
   deliberate: it tolerates concatenation and reformatting, and it over-keeps some genuinely dead
   keys, which is the correct direction to err.

   The escaped-form test is not optional. Keys arrive from `JSON.parse`, so they are unescaped,
   while source text spells them escaped — a key `Weird"Quote` is written `t.X["Weird\"Quote"]`.
   Testing only the raw form would report such a key dead **while it is live**, which is the one
   failure mode that reaches production as a blank string. Every key in both apps is plain ASCII
   today, so this was latent rather than active, but it means the tempting shorthand "substring
   matching can never miss a real literal" is only true once both forms are checked.
2. **Template prefix** — the key starts with a prefix extracted from `` `Prefix.${` `` in the
   corpus.
3. **Schema-form prefix** — the key starts with a `name:` value passed to
   `createUiSchemaWithResource`, or with `Form.` (the helper's default `name`).
4. **Literal prefix constant** — the key starts with a dot-terminated dotted-identifier string
   literal, e.g. `"CountryManagement."`.
5. **Allowlist** — an entry in `web-app/scripts/i18n-allowlist.json`. Each entry is
   `{ app, service, pattern, reason }`, where `pattern` is a literal key or a `*`-suffixed
   prefix matched with `startsWith`. `reason` is mandatory and states why the key is unreachable
   by static analysis.

### Why substring matching, concretely

A stricter quoted-literal matcher flags 139 additional keys. Those include `two-factor`,
`claims`, `bulk`, and `phones` from `AbpUiNavigation`, which are live: `provider.tsx` looks
them up by URL segment via `languageData[segment as keyof AbpUiNavigationResource]`. Strict
matching would delete working navigation labels. Substring matching keeps them because the
segment text appears elsewhere in the tree.

### Allowlist, initial contents

One entry: the Novu notification key families in `core/Default` —
`inbox.*`, `notification.*`, `notifications.*`, `preferences.*` (18 keys). The whole resource
object is handed to Novu's `<Inbox localization>`, which consumes keys by name internally, so
no key literal can ever exist in our code. This entry is required regardless of the wiring fix
below.

### CLI

```
node scripts/find-unused-i18n.mjs --app=web            # default: report, exit 1 if any found
node scripts/find-unused-i18n.mjs --app=ssr --prune
```

`--report` prints candidates grouped by service. `--prune` performs the deletion. A root
`package.json` script `"i18n:unused": "node scripts/find-unused-i18n.mjs"` makes re-running it
discoverable, which is the point of committing it.

## Pruning behaviour

- Deletes each dead key from `en.json` **and** `tr.json`.
- Deletion is line-based rather than a JSON re-serialisation, so surviving key order, escaping
  and the files' CRLF endings are preserved (verified across all 38 resource files in both apps:
  every one holds exactly one entry per line and uses CRLF). The diff is deletions only, with
  one unavoidable exception: when a file's
  *final* entry is deleted, its predecessor must lose its trailing comma, which git reports as
  one changed line. This happens in exactly three services — `CRMService`
  (`UniRefund.CRMService:026001`), `RefundService` (`CrossTenantPayout.Empty`) and
  `TravellerService` (`Permission:ProveDocument`) — so `web` yields 6 changed lines alongside
  822 deletions. No `ssr` file is affected.
- `tr`-only orphan keys (present in `tr.json`, absent from `en.json`) run through the same five
  layers with `tr.json` as the key source. They are unreachable through the type system but can
  resolve at runtime for the `tr` locale, so they get the same treatment rather than a blanket
  delete.

### Measured outcome

| App | Keys | Candidates | Allowlisted | Pruned (en) | Pruned (tr) |
| --- | --- | --- | --- | --- | --- |
| `web` | 3,351 | 427 | 18 (Novu) | 409 | 413 |
| `ssr` | 399 | 14 | 0 | 14 | 14 |

`web`'s tr count is higher because 4 of the 6 `tr`-only orphans fail all layers. The other 2
(`RiskLevel.ExportValidate.description`, `…descriptionPlaceholder`) survive via layer 3.

Largest dead families in `web`: `TagService/TagRisk` (56), `IdentityService/Organization` (24),
`TagService/ScanPassport` (22), `CRMService/CRM` (20), `IdentityService/User` (17),
`TagService/RefundStatus` (11). The `TagRisk` case is a good illustration of the detector
working: `operations/rule-engine` uses `TagRisk.AmountBasis.Sales` and
`TagRisk.ControlEvery.AllTags`, while the candidates are the superseded siblings
`TagRisk.AmountBasis.VatAmount` and `TagRisk.Frequency.AllTags`.

## Novu wiring fix

Discovered while validating candidates. `breadcrumb.tsx:132` passes `AbpUiNavigationResource`
into the prop that becomes `<Inbox localization>` in `packages/ui/src/notification/inbox.tsx`
and `popover.tsx`. The 18 Novu keys live in `core/Default`, and `AbpUiNavigation` has none of
them. Novu therefore falls back to its own English defaults, and the Turkish notification
strings someone wrote have never rendered.

These keys are dead by wiring bug, not by feature removal, so deleting them would destroy
intended translations. The fix repoints the wiring rather than relocating the data:

- Add `notificationLanguageData: DefaultResource` to `NavProps` in
  `components/sidebar-layout/data.ts`.
- Source it in `apps/web/src/app/[lang]/(main)/layout.tsx` via `core/Default`'s
  `getResourceDataClient`. Not `getResourceData` — that one also calls
  `getLocalizationResources`, which fetches the relative URL `/api/?lang=…` and cannot resolve
  server-side.
- Thread it through `sidebar-layout.tsx` → `breadcrumb/breadcrumb.tsx`.
- Pass it to `NotificationPopover`'s existing `langugageData` prop (note the upstream typo;
  leave it alone).

Four app files in total.

No changes to `packages/ui` — `NotificationProps.langugageData` is already the correct slot.
`breadcrumb.tsx` keeps its `languageData: AbpUiNavigationResource` prop for
`ReturnToPreviousPage`.

The alternative — moving the 18 keys into `AbpUiNavigation` — is a smaller diff but relocates
data to satisfy an accident and leaves Novu strings in the navigation resource. Rejected.

## Verification

`tsc --noEmit` is the primary gate, but it is a **narrower** gate than it first appears, and the
difference is worth stating precisely.

Because `getResourceData` types resolve to `typeof en`, deleting a key referenced through that
path fails the build. For the `t.Service[...]` path the types resolve from `i18n/*.gen.json`, and
`init.ts` builds that file by merging the ABP gateway's texts *underneath* the local JSON
(`texts[resourceName] = { ...texts[resourceName], ...jsonContent }`). So a key the server **also**
defines survives in the generated dictionary after its local entry is deleted, and `tsc` stays
green. Only keys that are local-only are actually caught there.

That same merge answers the backward-compatibility question: removing a local key the server also
defines breaks neither the types nor the `t.*` runtime lookup — it only means the server's wording
wins where a local override used to. Since none of the deleted keys is referenced anywhere at all,
no visible override was lost.

The baseline was confirmed green (`npx tsc --noEmit` in `apps/web` and `apps/ssr`, exit 0) before
any change.

Per change, **in this order** — `init` must run before `type-check`, or `tsc` still sees the
stale generated dictionary and the deletion goes unchecked:

1. `pnpm --filter web run init` — regenerates `i18n/*.gen.json` from the local JSON plus the ABP
   gateway. Needs `GATEWAY_URL` from `apps/web/.env` (`https://dev-api.unirefund.com`, confirmed
   reachable). Its two outputs — `i18n/*.gen.json` and `packages/utils/policies/policies.json` —
   are both gitignored, the latter inside the `packages/utils` submodule, so this adds no diff
   noise.
2. `pnpm --filter web run type-check` — must pass.
3. `pnpm --filter web run lint` — must pass.
4. `node scripts/find-unused-i18n.mjs --app=web` — must report zero remaining.

**Known verification limit:** the Novu inbox rendering Turkish strings needs a logged-in
session against the dev API. `tsc` proves the prop types line up, not that the strings render.
That confirmation is a manual step for the user, and must not be claimed as verified.

There is no unit-test runner in `apps/web`; Playwright exists but does not cover the
notification bell, and adding coverage for it is out of scope.

## Risks and rollback

The residual risk is a single pattern: `languageData[apiSuppliedValue]`, where the key comes
from server data and cannot appear as a literal. Every instance was traced:

- Settings display names — covered by layer 4 via `"CountryManagement."`.
- `earning.earningType` and `total.totalType` in the tax-free-tag cards — enum values are
  `None`, `GrossComission`, `RedefinedGC`, `Rebate`, `NetComission`, `FrontlineIncentive`,
  `MarketingIncentive`, `TourGuideFee`; none is in the candidate set.
- Novu — allowlisted.

Rollback is per-key: re-add one line to `en.json` and `tr.json`. A wrongly deleted key
degrades to a missing string in one UI location, not a crash, since every consumer either
renders `undefined` or has a `?? fallback`.

## Sequencing

1. Add the detector script, the allowlist, and the root `package.json` script. Confirm
   `--report` reproduces 427 candidates for `web` before the allowlist, 409 after.
2. Apply the Novu wiring fix.
3. Prune `web` (`--prune`). Verify. Commit.
4. Prune `ssr` (`--app=ssr --prune`). Verify. Commit separately.

Work happens on `web-app`'s current branch, `saas-update`, which was clean at design time. Note
that `packages/utils` is a git submodule; nothing in this work should modify it. Per the
shared-checkout hazard, no subagent may run `git reset --hard` in this working tree.
